## 6. Важно: один payment_id — один прогон

Тип счёта одноразовый, поэтому платёж «расходуется»:

| После какого вызова | Что происходит |
|---|---|
| `CreateTransaction` | счёт занят, новая транзакция → `-31053` |
| `PerformTransaction` | счёт оплачен → `-31051` |
| `CancelTransaction` | счёт отменён → `-31051` |

При повторном прогоне набора тестов **берите следующий ID из списка**.

Если свободные ID закончатся — напишите, выдадим новые в течение
нескольких минут.

## 7. Коды ошибок

### Ошибки счёта (диапазон `-31099 … -31050`)

| Код | Когда |
|---|---|
| `-31050` | счёт не найден · неверный формат · продавец заблокирован |
| `-31051` | платёж уже выполнен или отменён |
| `-31052` | истёк срок действия ссылки на оплату |
| `-31053` | по счёту есть незавершённая транзакция |

Все сообщения приходят на трёх языках (`uz`, `ru`, `en`), поле `data`
содержит `payment_id`.

### Остальные

| Код | Когда |
|---|---|
| `-32504` | ошибка авторизации |
| `-31001` | сумма не совпадает |
| `-31003` | транзакция не найдена |
| `-31008` | состояние **транзакции** не позволяет операцию |

`-31008` возвращается только из `PerformTransaction` и
`CancelTransaction`. Для состояний **счёта** всегда используется
диапазон `-31050 … -31099`.

## 9. Особенности реализации

- **Таймаут 12 часов.** Транзакция в состоянии `1` старше 43 200 000 мс
  отменяется автоматически: `state = -1`, `reason = 4`.
- **Идемпотентность.** Повторный `CreateTransaction` или
  `PerformTransaction` с тем же `id` возвращает тот же ответ и не
  создаёт повторный эффект.
- **Одна активная транзакция на счёт.** Второй `CreateTransaction` с
  новым `id` по тому же счёту → `-31053`.
- **`GetStatement`** ищет по времени создания на стороне Payme
  (`params.time`), обе границы включительно, сортировка по возрастанию.

---

## 10. Контакт

При любой ошибке пришлите, пожалуйста:

- название теста;
- использованный `payment_id`;
- тело запроса и тело ответа;
- время (с точностью до минуты).

По этим данным мы находим запрос в журнале и отвечаем в тот же день.
